2b. Infrastructura si verificare

IN VIGOARE DIN 27 SEPT scripts/documente.tsv — manifestul: singura sursa de adevar despre ce exista. Un rand = un document = o pereche RO+NO.
scripts/verifica-site.sh v3 — verifica intregul site contra manifestului, in 13 sectiuni: manifest, inventar, antet SEO (titlu, lang, description, canonical, hreflang ro/nb/x-default, og), linkuri si ancore, prezentarea in hub, sitemap-uri, formulari retrase, cifre declarate, structura HTML, ADN-ul repo-urilor, starea git, pagina GitHub (About), afirmatiile [13].
scripts/hooks/pre-push — identic, bit cu bit, in toate cele 6 repo-uri (core.hooksPath scripts/hooks). La fiecare push, din oricare repo, se verifica tot site-ul, cu starea adusa de pe GitHub.
scripts/retrase.txt — formularile corectate, care nu mai au voie sa reapara nicaieri.
scripts/afirmatii.tsv — registrul afirmatiilor de fond: eticheta (FAPT, ESTIMARE, INTERPRETARE, CREDINTA), stare, sursa, an. Afirmatia se marcheaza in pagina cu <span data-afirmatie="id">, in RO si in perechea NO. Verificat de [13]: registru, perechi RO-NO, datoria de verificare (ATENTIE, nu blocheaza).
scripts/certitudini.txt si certitudini-ok.txt — detectorul de certitudine din [13]: cuvinte ca „a demonstrat”, „singurul”, „har dokumentert”, cautate pe cuvinte intregi in textul nemarcat; semnaleaza, nu blocheaza. Fragmentele citite si acceptate intra in certitudini-ok.txt.
scripts/about.tsv — caseta About a fiecarui repo pe GitHub (descriere, website, topics); verificata la fiecare push prin API.
.github/workflows/verifica.yml — a doua plasa: GitHub Actions ruleaza acelasi verifica-site.sh (--ci) pe starea de pe GitHub, la fiecare push si zilnic; prinde si editarile facute direct in browser. Identic in toate cele 6 repo-uri.
Autentificare — push prin SSH: cheie ed25519 dedicata (~/.ssh/id_ed25519_github, cu parola, tinuta de ssh-agent), prin ssh.github.com:443 (firewall-ul pf permite doar anumite porturi; 22 nu e printre ele). Fetch pe HTTPS, fara autentificare (repo-uri publice). Niciun token: sters de pe masina si de pe GitHub pe 27 sept.
Identitate si licenta — commit-urile se fac cu adresa noreply GitHub (verificat in fiecare clona); LICENSE = textul oficial CC BY 4.0, identic in toate cele 6; sectiunea de licenta identica in toate README-urile.
Testat: mediu non-GNU (dash, one-true-awk, busybox), GNU si OpenBSD — verdicte identice; 20 de teste cu defecte introduse intentionat, prinse toate. Sectiunea [13]: 38 de teste, plus contra-proba pe scriptul vechi (testele pozitive trebuie sa pice acolo).

5. Comenzi

COMENZI Clonele locale (surori, toate in /home/bogdan): norgedan.github.io · corpus · corpus2 · opera · limba · limba-ro-final

Inceput de sesiune — starea tuturor fata de GitHub:
for r in norgedan.github.io corpus corpus2 opera limba limba-ro-final; do git -C ~/$r fetch -q origin; echo "$r $(git -C ~/$r status -sb | head -1)"; done
Fiecare linie trebuie sa fie ## main...origin/main, fara [behind] sau [ahead].

Verificare manuala oricand: sh ~/norgedan.github.io/scripts/verifica-site.sh — trebuie EXIT=0
Plus paginile GitHub (retea): sh ~/norgedan.github.io/scripts/verifica-site.sh --github
Doar tabloul: sh ~/norgedan.github.io/scripts/verifica-site.sh --tablou

Aplicarea unui patch: sha256 pe fisierul descarcat, git apply --check, git apply, git add -A, git diff --cached --raw comparat cu hash-urile asteptate, apoi commit. Push-ul verifica singur.

Capcane BSD/POSIX: fara \n in sed · fara \| in grep · fara sed -i · fara litere multibyte intre paranteze drepte · fara <( ) (e bash) · optiunile grep inaintea tiparului · sha256, nu sha256sum · niciodata sabloane <...> in comenzi · nu lipi output in shell (-> FETCH_HEAD creeaza un fisier) · tar pe OpenBSD: lista de fisiere cu -I fisier, nu -T · dupa o cerere de parola, comenzile lipite in continuare se pierd: o comanda pe rand
