De ce contează atașamentele

Textul de mai sus dă direcția și standardul. Ghidul și statusul dau detaliile — proceduri pas cu pas, greșelile deja făcute și lecțiile lor. Fără ele, o discuție nouă pornește de la zero și repetă erori deja rezolvate. Atașează-le din repo, nu din Downloads: o copie rămasă în Downloads poate fi alta decât cea publicată.

Dacă se lucrează pe texte

Textele Bibliei nu persistă între discuții, deci se reatașează de fiecare dată când se verifică citate. Pe mașina ta, secțiunea [14] le confruntă singură la fiecare push, din ~/biblii. Fără ele, orice verset ar fi scris din memorie — ceea ce standardul nu permite.

Rutina de sesiune

La început: starea tuturor clonelor față de GitHub — fiecare linie trebuie să fie ## main...origin/main:

for r in norgedan.github.io corpus corpus2 opera limba limba-ro-final; do git -C ~/$r fetch -q origin; echo "$r $(git -C ~/$r status -sb | head -1)"; done

Apoi ~/Downloads golit de patch-urile vechi, ca orice descărcare nouă să fie fără echivoc cea nouă.

La fiecare patch: git apply o singură dată — a doua rulare dă eroare doar pentru că patch-ul e deja aplicat. Amprentele de la git diff --cached --raw se compară cu cele din discuție înainte de commit.

La push: verificarea rulează singură, local și apoi pe GitHub. Dacă push-ul e blocat, citește liniile PROBLEMA și repară cauza — nu ocoli garda. Dacă „publica” iese roșu în Actions, site-ul live rămâne neatins până la reparare.

La sfârșit: golește Downloads. Verificarea semnalează singură orice fișier rătăcit în rădăcina unui repo.
